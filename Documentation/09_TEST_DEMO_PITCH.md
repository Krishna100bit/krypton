## 1. Test strategy
| Layer | What | How | Owner |
|-------|------|-----|-------|
| Domain (Dart) | Reminder rules, draft state machine, daily summary, WAV writer | `flutter test` (written by hand, see file 07) | App dev |
| Pipeline (Python) | Validator, repair, chunk merge, date resolution | `pytest` | Backend dev |
| AI quality | Zoning, actions, owners, deadlines | `eval/run_eval.py` against golden fixtures | AI lead |
| Integration | Phone record → upload → minutes → reminders | Manual checklist on a real phone | QA |
| Hardware | Locket stream quality, reconnect, range | 3 × 5-minute soak tests | Hardware |
| Safety | No send without approval, consent shown | Unit tests + manual attempt to bypass | QA |

## 2. Test data
- **Synthetic:** 5–7 meetings generated by an LLM with a hidden answer key (decisions, actions, owners, deadlines). Include tricky cases: unassigned action, deadline stated vaguely ("sometime next week"), a decision reversed later, small talk, interruptions.
- **AMI-style:** 3 clips/transcripts for realism.
- **Audio:** record 2–3 teammates reading/acting scripts in a quiet room and in a noisy room; one clip from the locket, one from the phone, one uploaded file.
- **Speaker ID:** enrollment samples for 3 teammates + one unenrolled voice (to test false accepts).

## 6. Judge Q&A prep
| Question | Answer |
|----------|--------|
| How is this different from Otter/Fireflies? | Semantic zoning with decisions/actions as first-class, wearable + phone capture, speaker enrollment, rule-based reminders, human-approved actions, offline tiers, open-source stack. |
| How accurate is it? | Show the eval table; state the test set size honestly; mention the validator and repair step and that unassigned owners are flagged. |
| What if the LLM hallucinates an action? | Evidence is referenced by utterance index, each action links to its source line, low-confidence items are flagged, and nothing external happens without approval. |
| Privacy? | Consent prompt, recording indicator, local-first storage, delete wipes audio/embeddings, keys stay on the server, optional fully local mode (Tier B/C). |
| Why rule-based reminders? | Deterministic, testable, offline; LLM only extracts deadline and priority. |
| Does the offline mode really work? | Tier B: local server with an open model, no internet. Tier C: on-device small model summarizes structured minutes; extractive fallback guarantees output. Be upfront that full zoning quality is best in Tier A/B. |
| Speaker ID in noisy rooms? | Confidence is shown, a threshold is tuned, unknown speakers stay labeled, and the user can rename and enroll. |
| Can it send emails by itself? | No, by design: drafts only, explicit confirmation required, enforced and tested in code. |
| What would you build next? | Battery + enclosure, live captions, calendar/Slack integrations, team workspaces, multilingual. |
